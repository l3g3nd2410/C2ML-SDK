# Patching game code with Harmony

Menu widgets and config cover your mod's interface and settings, but to change the **game's own behavior**
(tweak a computed value, intercept an event, prevent an action...), you need to patch an existing game method.
That's what [Harmony](https://harmony.pardeike.net/) (`0Harmony.dll`, included in the SDK's `lib\`) does.

## Why this works on an IL2CPP game

CarX Drift Racing Online 2 is a Unity game compiled to IL2CPP (native code, not a plain .NET assembly you can
read with a classic decompiler). On its first launch, the loader generates **interop assemblies** (in
`C2ML\cache\unity-libs\` and `C2ML\interop\`): C# types shaped exactly like the game's code, relaying every call
to the real native code underneath. Harmony patches these interop types normally, just like any other .NET
assembly - the only difference from a classic Mono game is that the patched type isn't the "real" code, but a
transparent relay to it.

## Referencing Harmony in your project

```xml
<Reference Include="0Harmony">
  <HintPath>path\to\C2ML-SDK\lib\0Harmony.dll</HintPath>
  <Private>false</Private>
</Reference>
```

## Applying and removing patches

```csharp
using HarmonyLib;
using System.Reflection;

public override void OnLoad()
{
    _harmony = new Harmony(GetModGUID());        // unique id, see 02-mod-lifecycle.md
    _harmony.PatchAll(Assembly.GetExecutingAssembly());
}

public override void OnUnload()
{
    _harmony?.UnpatchSelf();   // removes every patch applied by THIS Harmony instance
}

private Harmony? _harmony;
```

`PatchAll(assembly)` scans your assembly for classes marked `[HarmonyPatch(...)]` and applies each one
automatically - no need to call `Patch()` by hand for every method.

**`OnUnload()` must always remove the patches it applied.** Otherwise the patch would stay active in the game
even after the player disables your mod from Manage mods, which can cause unexpected behavior or conflicts with
other mods.

## Writing a patch

A static nested class per patched method, with `[HarmonyPatch(type, memberName)]`:

```csharp
[HarmonyPatch(typeof(UnityEngine.Time), nameof(UnityEngine.Time.timeScale), MethodType.Setter)]
private static class TimeScalePatch
{
    private static void Postfix()
    {
        // runs AFTER Time.timeScale has been changed by the game: we're just observing, not blocking anything
        C2ML.API.Logging.Logger.Log("[My Mod] timeScale changed");
    }
}
```

- `MethodType.Setter` targets a property's "set" (`MethodType.Getter` for the "get"). Omit this parameter to
  target a normal method by name.
- A patch class is **static**: it has no access to an instance of your mod. To log or touch your mod's state
  from a patch, use the global logger (see [06-logging.md](06-logging.md)) and store shared state in a `static`
  field on your mod class.

### `Postfix` vs `Prefix`

| | Runs | Can prevent the original | Typical use |
|---|---|---|---|
| `Postfix` | After the original method | No | Observe a result, tweak it slightly (`ref __result`) |
| `Prefix` | Before the original method | Yes (`return false`) | Fully block a behavior, replace a value before it's computed |

```csharp
[HarmonyPatch(typeof(SomeGameClass), "SomeMethod")]
private static class MyPatch
{
    // Can block the original from running if it returns false
    private static bool Prefix()
    {
        return true;   // let the original run normally
    }

    // Can read/modify what the original returned
    private static void Postfix(ref bool __result)
    {
        // __result holds what the original returned; changing it here changes what callers receive
    }
}
```

A class can have both `Prefix` and `Postfix` at the same time if needed.

## Finding the right method to patch

The interop assemblies generated by the loader (`C2ML\cache\unity-libs\`, `C2ML\interop\`) are normal .NET
DLLs: open them with [dnSpy](https://github.com/dnSpyEx/dnSpy) or [ILSpy](https://github.com/icsharpcode/ILSpy)
to explore the game's available classes and methods, exactly like with a classic Mono mod. That's outside the
scope of this SDK (specific to the game's own code, not to the C2ML API itself), but it's the starting point:
find the type and method you're after in the decompiler, then write the patch as shown above against that
type/method.

## Full example

See `TimeScalePatch` in `C2ML.ExampleMod\ExampleMod.cs` - a working, harmless patch (it only observes changes
to `Time.timeScale`, modifies nothing) you can run in game to see the whole mechanism work end to end before
writing your own patch against a real game method.
